# 프로젝트 분석 · 2026-10-22

개인·2주 개발은 사용자 확인 사항이다. 아래는 현재 로컬 코드 정적 분석과 제한된 자동 검사 결과다. 실제 사이트 재수집·DB 접속은 하지 않았다.

## 데이터 흐름과 책임

- `src/main.py`: 사이트·카테고리·수집 수 선택 → 목록 URL → 상세 파싱 → 상품 저장 → 수집 결과 로그.
- `src/crawler_config.py`: 컴퓨존/다나와와 CPU/GPU/RAM/SSD/MOTHERBOARD 클래스를 매핑.
- `src/crawlers/compuzone`: Requests 세션·BeautifulSoup 및 부품별 파싱.
- `src/crawlers/danawa`: Selenium 동적 목록·페이지 처리와 상세 추출.
- `src/normalizers`: 상품명 정규화·RAM/SSD 규격 포함 키. 전용 메인보드 매칭은 `product_matcher.py`.
- `src/db`: 기준 상품·상세 규격·판매/가격 이력 저장, 통계·기본 호환성 조회, 수집 로그.
- `web/app.py`, `web/templates`, `web/static`: 목록·상세, 규격 필터, 가격 차트, 기본 호환성 화면.

## 확인한 제한

상품 간 완전 매칭이나 전체 조립 호환성은 보장하지 않는다. 기본 호환성은 소켓·메모리 타입 비교다. 제공된 SQL 두 개는 RAM 정리 목적이며 전체 스키마 초기 생성 DDL이 아니다. 실데이터 DB 구조는 이번에 조회하지 않았다.

과거 문서는 요청 간격 35~40초지만 실제 진입점은 20~25초다. requirements는 문자 형태의 역슬래시+n을 포함한 한 줄이다. 설정·코드는 이번 문서 작업에서 바꾸지 않았다.

## 포트폴리오 근거

수집·정제·저장·조회가 연결된 통합 데이터 처리 프로젝트로 설명한다. 기술 선택의 개인적인 배경과 본인의 시행착오 상세는 기록에 없는 내용을 만들어내지 않는다. 스크린샷은 추후 사용자 촬영본으로 추가한다.
